# МойАльфаКредит — кредитный конвейер для МСБ

«Ответ известен до подачи»: предприниматель вводит ИНН, видит в песочнице предварительную оценку кредита
(шанс одобрения, лимит, ставку, ПСК и сценарии «что если»), подаёт заявку одной кнопкой и следит за ней в живом
трекере статусов до зачисления денег. Решение принимает автоматический конвейер на обученном движке скоринга;
сложные заявки (крупная сумма, залог, сбой внешнего сервиса) уходят в кабинет аналитика. Рядом — персональная
лента новостей и помощник ИИгорь.

Все компании, учётки и внешние сервисы в демо вымышлены или имитированы (см. «Что реальное, что синтетика, что мок»).

## Быстрый старт

```
cp .env.example .env        # необязательно: без .env берутся значения по умолчанию
docker compose up --build
```

- Приложение: http://localhost:8080
- Swagger UI: http://localhost:8080/api/docs, схема OpenAPI: http://localhost:8080/api/openapi.json (копия — `docs/openapi.json`)
- Проверка живости: http://localhost:8080/api/health

Поднимаются два сервиса: `db` (PostgreSQL 16.6, том `pgdata`) и `app` (FastAPI + собранный фронт, порт 8080 → 8000
в контейнере). Приложение стартует после healthcheck базы; таблицы создаются при первом запуске.

## Пошаговая проверка

1. `docker compose up --build`, открыть http://localhost:8080, войти как «Марина Соколова» (`client`).
2. Ввести ИНН `0010000017` — карточка компании из мока ЕГРЮЛ, затем песочница.
3. **T2.** Песочница показывает «Нужно согласие на запрос в БКИ». Нажать «Дать согласие на запрос в БКИ» —
   «Можем выдать 3,61 млн ₽» с причиной про денежный поток (DSCR ≥ 1,25).
4. **T1.** В сценарии «Взять на 24 месяца» нажать «Применить» — «Одобрим 6 млн ₽ на 24 мес.».
5. Нажать «Подать заявку», отметить «Согласен на запрос в бюро кредитных историй», «Отправить в банк».
6. Открывается трекер `#/applications/<id>`: шаги Подана → Проверка данных → Скоринг проходят сами
   (по 1,2 с), затем «Одобрено», ход клиента.
7. «Принять предложение» → статус «Подписание», на экране код подписи из 4 цифр.
8. Ввести код, «Подписать» → статус «Выдано», карточка кредита (номер договора, сумма, ставка, платёж).
   Журнал внизу трекера показывает каждый переход.
9. **T5.** Подать заявку по ИНН `0020000023` («Северный хлеб», залог 15 млн ₽) — статус «У аналитика».
   Выйти, войти как «Аналитик МСБ» (`analyst`), открыть `#/analyst`: заявка в очереди, в карточке — факты,
   PD, класс риска, балл, шанс, причина маршрута. Одобрить с комментарием (без комментария — ошибка) →
   «Одобрено». Клиент видит решение в своём трекере.
10. Остальные сценарии (T3, T4, T6, T7) и тот же путь через API — `docs/test-scenarios.md` и коллекция
    `docs/postman_collection.json`.

## Ограничения

- Демо-вход: учётки в коде, без смены пароля и отзыва токена (токен живёт 12 ч).
- Схема БД создаётся `create_all` при старте, миграций (Alembic) нет.
- Воркер автоматических шагов работает в одном процессе приложения; для нескольких реплик нужен вынесенный
  воркер (переходы при этом уже атомарны и не задвоятся).
- Загрузка документов имитируется: файлы не принимаются, факты дополняются из `after_docs` демо-компании.
- Абсолютные PD и ставки иллюстративные: метка дефолта и БКИ синтетические (см. «Движок скоринга»).

## Движок скоринга

Кредитный скоринг малого и среднего бизнеса на **реальных юрлицах** из открытых данных ФНС и ГИР БО:
вероятность дефолта (PD-скоркарта), шанс одобрения, кредитное решение с лимитом, risk-based ставка с капиталом
по ПВР (Положение Банка России 845-П), честная ставка (ПСК) и сценарии «что если» — с понятными причинами.

На Windows команда `python` может открывать заглушку Microsoft Store — тогда вместо неё `py`.

### Что реальное, а что синтетика

| Данные | Источник |
|---|---|
| Оборот, возраст, ОКВЭД, долг/выручка, долг/EBIT, капитал/активы, покрытие процентов, DSCR, рост выручки, налоговый долг | **реальные**: ФНС opendata (`revexp` — доходы, `debtam` — налоговый долг), ГИР БО bo.nalog.gov.ru (отчётность за 5 лет) |
| Фондирование | **реальная** G-кривая Мосбиржи на D-1 |
| Просрочки БКИ, сезонность выручки, продукт, сумма, РКО, маркетплейс, гарантия, страховка | **синтетика** — в открытом доступе нет |
| Факт дефолта `default_12m` | **синтетика** — скрытая логика с шумом (`scoring/synth.py`) |

Только юрлица (ИНН из 10 цифр); ИП — физлица, в выборку не берутся.

### Модели

**PD-скоркарта** (`scoring/scorecard.py`): OptBinning, 8–12 факторов по IV, монотонные бины, 600 баллов при
odds 50:1, PDO 20; PD калибруется на отложенной выборке, классы риска 1–7. Gini в отчёте — среднее ± разброс по
5 стратифицированным фолдам (отбор факторов и биннинг заново на каждом), без удачи одного разбиения. Коды причин
R01–R12 — факторы с наибольшей потерей баллов, свёрнутые в категории («высокая долговая нагрузка», «короткая история
оборотов», …).

**Кредитная логика** (`scoring/credit.py`, `config/credit_policy.json`): стоп-факторы S01–S07 → отказ; нет
ключевых данных → дозапрос документов; лимит = min(доля оборота по классу, аннуитет при DSCR ≥ 1,25 по ставке
модели); исходы APPROVE / COUNTER / REQUEST_INFO / REJECT. Контрпредложение объясняет, что ограничило сумму:
L02 денежный поток при DSCR ≥ 1,25, L03 доля оборота, L04 максимум продукта, L05 обороты в банке у овердрафта,
L06 минимальная сумма — а не баллы скоркарты. **Без тупиковых отказов**: не подошёл продукт
(возраст, нет РКО или маркетплейса, лимит ниже минимума) — бизнес-карта, кредит селлерам или залоговый кредит
с причиной.

**Шанс одобрения** (`scoring/approval.py`): логистическая регрессия на решениях кредитной логики. Признаки —
категории заявки (продукт, возраст бизнеса, РКО, обороты в банке / лимит, сумма / выручка, маркетплейс, гарантия
МСП, просрочки БКИ; у каждого признака референс), PD скоркарты, запас денежного потока ((EBIT / 1,25 −
обслуживание долга) / годовой платёж) и ln(оборот / платёж); платёж — аннуитет по ставке модели цены для заявки,
как в DSCR-лимите (ставка неизвестна — по опорной 22,5%). Знаки
ограничены смыслом: залог, РКО, обороты в банке, маркетплейс, гарантия и денежный поток не снижают шанс, PD, сумма,
просрочки и молодость бизнеса не повышают, упорядоченные категории монотонны — what-if не противоречит решению.
Запас — отдельные наклоны до 0,5× и 0,5–1× платежа и ступень на 0,5× (контрпредложение от половины суммы — уже
одобрение), выше 1× не растёт: лимит по DSCR не режет. Учится на 70% решений; Brier и калибровка по классам риска и
по полосам запаса — на отложенных 30%, Gini — среднее ± разброс по 5 стратифицированным фолдам. Soft-режим: нет БКИ или
отчётности — признак получает средний вклад по обучению, ответ помечен `approval_mode: soft` со списком
`approval_imputed`. Балл = 600 + (20/ln2)·logit, баллы категории = (20/ln2)·β. Это модель политики, риск — PD.

**Ставка** (`scoring/pricing.py`, `config/pricing.json`, параметры иллюстративные): фондирование (G-кривая на
D-1 + спред) + PD×LGD + капитал + расходы + маржа − скидки (обороты в банке, подписка, страховка); ПСК — с
комиссией и страховкой.

**Капитал по ПВР** (`scoring/irb.py`, 845-П): вес риска из PD — заявка до 70 млн руб. как розничное МСП
(собственный LGD не ниже пола 30%), крупнее — корпоративное требование базового ПВР (LGD 40%, залог по
п. 17.7, M = 2,5, скидка к корреляции для МСП по выручке). Формула сверена с иллюстративной таблицей Базеля
(PD 1%, LGD 45% → 92,32%); `"approach": "standard"` — плоский вес.

### Проверка на реальной метке (ЕГРЮЛ)

Для недействующих компаний выборки загрузчик берёт из ЕГРЮЛ способ прекращения и состояние (только их, даты и
роль руководителя — без ФИО; выписки не сохраняются). Событие — банкротство или исключение налоговой после
подачи отчёта; ликвидации и реорганизации не считаются. Компании делятся пополам по хэшу ИНН: на одной половине
подбираются веса реальных слагаемых скрытой логики дефолта (L2-логит, банкротство весит ×5 относительно
исключения, знаки ограничены смыслом, налоговый долг не подбирается — срез ФНС бывает позже события), на другой
отчёт `train_scorecard.py` считает Gini скоркарты с бутстреп-интервалами. Банкротство датируется первой
записью о процедуре несостоятельности в реестре (наблюдение, внешнее управление, признание банкротом): в выборке
51 банкротство, но после подачи отчёта началось только 12 — для подбора кредитной логики этого мало, поэтому
подобранные веса применяются только по ключу `--calibrated-weights`, по умолчанию веса ручные.

```
py scripts/load_egrul.py             # ~520 компаний, 1 запрос в 3 с (~2,5 ч), стоп на капче и не-JSON ответах
py scripts/calibrate_synth.py        # config/synth_calibration.json
py scripts/build_scoring_sample.py   # выборка из ФНС (ручные веса; --calibrated-weights - подобранные)
py scripts/train_scorecard.py --capital-approach both
```

### Песочница кредита (веб)

Дашборд «Песочница кредита» по `docs/dashboard-igor-spec.md` и `DESIGN.md`: API `api/` (FastAPI) поверх движка и
фронт `web/` (React + Vite). Демо-компании вымышлены (`demo/personas/`, ИНН с несуществующим регионом 00): реальные
компании выборки в песочницу не попадают, к ним приклеены синтетические БКИ и дефолты.

```
py scripts/check_personas.py                 # исходы демо-компаний и числа Марины из защиты на data/scoring/engine.pkl
py -m uvicorn --factory api.app:create_app --port 3100   # API (ENGINE_PATH, иначе data/ или models/engine.pkl), Swagger /api/docs
cd web; npm ci; npm run dev                  # http://localhost:5173, /api проксируется на 3100
cd web; npm test; npm run build              # тесты и сборка фронта
cd web; npx playwright test                  # золотой путь Марины и все демо-компании (нужны API и Vite)
bash scripts/deploy.sh                       # деплой на VPS (первый раз --setup); DEPLOY_HOST, DEPLOY_DOMAIN, DEPLOY_KEY, ENGINE_PATH - в .env
```

На сервере: код в `/opt/alfa-credit`, модель `/var/lib/alfa-credit/engine.pkl`, сервис `alfa-credit` (uvicorn на
127.0.0.1:3100, `MemoryMax` 450 МБ), сайт Caddy `/etc/caddy/sites/alfa-credit.caddy`. Версии библиотек на сервере —
ровно `deploy/requirements-server.txt`: иначе pickle движка не загрузится.

### Структура

```
scoring/   признаки и синтетика, скоркарта, причины, кредитная логика, одобрение, цена, ПВР, what-if, G-кривая
scripts/   загрузчики (ФНС, ГИР БО, G-кривая), сборка выборки, обучение и отчёт, оценка компании
config/    кредитная политика и параметры цены
notebooks/ демо
reports/   отчёты скоркарты
tests/     тесты (фикстуры синтетические, кроме публичной G-кривой Мосбиржи)
api/       HTTP API песочницы: контракт ответов, демо-компании
demo/      вымышленные демо-компании песочницы
web/       фронт песочницы (React + Vite), e2e на Playwright
deploy/    настройка VPS, systemd, Caddy, точные версии для сервера
models/    обученный движок (engine.pkl) для песочницы и команды
```

### Ограничения

Метка дефолта, БКИ, сезонность и поля заявки синтетические: механизм и интерфейс настоящие, абсолютные PD и
ставки иллюстративные. Одобрение известно только для выданных кредитов — на реальных данных нужен reject
inference.
